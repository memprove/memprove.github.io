memprove GitHub Releases Guide

Agent memory that is checked, not trusted.

memprove is a memory and task-state layer for coding agents. Every fact an agent records is bound to a commit, a repository state and a test run, and a deterministic rule, not a model, decides whether it still holds.

Download v0.1.0 Source on GitHub

Why not just notes?

Agent memory goes stale silently: a note says the parser handles empty input, and three commits later it does not. memprove does not judge text. A fact is verified only while a test run recorded with memprove run passed in the repository state the daemon can still observe.

verified

A passed run of the current HEAD, index and worktree backs the fact.

stale

The repository moved since that run; the Pack says which command to run again.

tampered

The ledger was changed behind the daemon's back; the word "verified" appears nowhere.

The record is a hash-chained ledger kept by a local daemon. A new session, whether the same agent later, another agent or a person, reads a compact Context Pack of what holds, what is open and what to do next. Everything runs on your machine over a Unix socket; nothing leaves it.

Install

macOS on Apple silicon and Linux x86_64 have release archives:

target=aarch64-apple-darwin        # or x86_64-unknown-linux-gnu
curl -LO https://github.com/memprove/memprove/releases/download/v0.1.0/memprove-0.1.0-$target.tar.gz
tar -xzf memprove-0.1.0-$target.tar.gz && cd memprove-0.1.0-$target
scripts/install.sh --from-binaries bin   # installs into ~/.memprove and starts the daemon

Elsewhere, build from source: cargo fetch --locked, then the offline release build and scripts/install.sh, as the README shows.

One session

memprove init                                   # once per repository: hook, MCP entry, doctor
memprove begin --new-task "parser: handle empty input"
memprove run --test-format cargo -- cargo test   # the run is the Evidence (r1)
memprove checkpoint create \
  --fact "the parser accepts empty input" --evidence r1 \
  --open "the truncated-header path is untested" \
  --next "write the truncated-header test"
memprove resume --pack                          # what the next session reads
memprove end --reason "empty input handled"

In Claude Code the SessionStart hook injects the Pack at the start of every session, and the MCP server offers the same operations as tools; Codex and Cursor get the MCP entry and a short note.

Taking over

A Pack lists every Session that has not ended. A session that finds one left by another agent ends it as abandoned only when three conditions hold: it is not its own, it looks gone, and it is not its parent. Otherwise it leaves it open and records that another Session may still be working.
